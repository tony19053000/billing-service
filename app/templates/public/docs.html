Tallyo API Quickstart

Welcome to the Tallyo Developer Documentation. Tallyo gives your software product a turn-key billing engine: subscription management, deterministic credit drawdowns, entitlement gating, and customer invoices.

Base URL

All REST requests are prefixed with /api/v1:

Endpoint Root
https://api.tallyo.io/api/v1 (Production)
http://localhost:8000/api/v1 (Local Development)

Authentication & Sessions

Tallyo uses opaque random bearer tokens. You authenticate API requests by providing your token in the standard HTTP Authorization header.

HTTP Header 
Authorization: Bearer <token>

When interacting with the customer billing portal in a browser, sessions are also stored in a secure tallyo_session cookie.

Errors & Status Codes

Tallyo returns standard HTTP status codes along with a JSON error payload containing a machine-readable code and human-readable message:

JSON Error Response (e.g. 402 Payment Required)
{
  "error": {
    "code": "insufficient_credits",
    "message": "Workspace has insufficient credit balance (current: 12, required: 50)"
  }
}
Status Error Code Description
401 unauthorized Invalid or expired bearer token
402 insufficient_credits Workspace balance cannot cover the requested usage event
404 not_found The requested entity does not exist in your workspace
409 conflict The resource already exists (e.g. email duplicate or duplicate operation)

Subscriptions & Proration

Subscriptions track recurring plan access. Tallyo supports 3 built-in plans: Starter ($0/mo), Pro ($49/mo or $490/yr), and Business ($199/mo or $1,990/yr).

When an upgrade occurs, Tallyo calculates the exact second-level proration of the remaining period, credits the previous plan's unused value, and issues an immediate invoice and charge for the difference. The higher credit allocation is granted immediately.

Change Plan Request
curl -X POST http://localhost:8000/api/v1/subscription/change-plan \
  -H "Authorization: Bearer $TALLYO_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "plan_id": "plan_pro",
    "interval": "month"
  }'

Usage Credits & Idempotency

Credits power consumption billing. Usage events are ingested via POST /api/v1/usage across three supported metrics:

  • api_calls: 1 credit per invocation
  • exports: 50 credits per data export job
  • ai_tokens: 1 credit per 100 tokens (rounded up)
Ingest Usage with Idempotency
curl -X POST http://localhost:8000/api/v1/usage \
  -H "Authorization: Bearer $TALLYO_TOKEN" \
  -H "Idempotency-Key: job_req_99210_token_eval" \
  -H "Content-Type: application/json" \
  -d '{
    "metric": "ai_tokens",
    "quantity": 2500
  }'

Invoices & Receipts

Invoices are generated automatically on period renewal, plan upgrades, and credit pack top-ups. Each invoice contains an immutable identifier like TLY-2026-00042, detailed line items, and a tax breakdown.

You can retrieve printable HTML/PDF invoices via GET /api/v1/invoices/{id}/pdf, which features a custom print stylesheet designed for executive accounting and expense auditing.

Simulation Test Clocks

Tallyo eliminates flaky asynchronous timers. The platform relies on a deterministic test clock that simulates the passage of time on demand. When you advance the clock, Tallyo executes billing cycle rollover, evaluates pending cancellations, and renews active periods synchronously.

Advance Clock by 30 Days
curl -X POST http://localhost:8000/api/v1/clock/advance \
  -H "Authorization: Bearer $TALLYO_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "days": 30
  }'

API Reference

POST /api/v1/usage

Record a billable consumption event against the authenticated workspace's credit ledger.

HTTP Request
curl -X POST http://localhost:8000/api/v1/usage \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"metric": "api_calls", "quantity": 100}'
GET /api/v1/workspace/features/{key}/check

Direct check to see if a workspace is entitled to a specific feature flag (e.g. sso_saml, webhooks).

JSON Response
{
  "allowed": true
}
